# Dev Rules

## 哲學與心態

### 核心哲學
- 低耦合：模組間以明確的 I/O 邊界串接，各單元可獨立替換
- fail fast：遇到異常立即報錯中止，不靜默繼續
- 契約優先（Contract-First）：介面與型別定義先於實作
- 強型別約束：杜絕隱式轉型與不明確的型別邊界
- 代碼即耗材（Disposable Code）：可替換優於可維護

### 邊際效益思維
- 提出方案、修改、開發之前，先評估邊際效益
- 避免邏輯100分但邊際效益極低的建議或操作

## 容錯與穩健性

### 故障處理
- 單一模組失敗應明確報錯，不靜默影響其他流程
- 錯誤明確往上傳遞，禁止在中間層吞掉例外

### 啟動驗證（Python）
- 啟動時驗證所有快取與路徑均指向 TMP/，否則 fail fast，不進入主流程
- AI 應用若 GPU 可用，必須使用 GPU，禁止靜默回退至 CPU

## 開發品質

### 測試策略
- 自動化測試先行，測試覆蓋作為可交付條件之一

### 環境一致性（Python）
- 透過 uv run 建立獨立環境執行，完全不依賴全域 pyproject.toml
- AI 模型載入：torch_dtype 統一改為 dtype

## 路徑與 I/O 管理（Python）

### 路徑基準
- 所有路徑以 Path(__file__).parent.resolve() 為基底
- 禁止 CWD 相對路徑，Path("TMP")、os.getcwd() 均不合規

### 三層分離
- INPUT / OUTPUT / TMP 明確分離，禁止跨層混寫

## 快取與暫存隔離（Python）

### 動機（根本原因）
- 作業系統硬碟與開發工作資料夾位於不同實體硬碟
- 所有快取與暫存必須留在開發碟，禁止任何形式寫入系統碟
- 這是以下所有規則的共同動機，違反任一條即視為違反此原則

### 寫入限制
- 所有暫存、快取、中間檔寫入腳本目錄下的 TMP/
- 禁止寫入 ~/、/tmp、~/.cache（均位於系統碟）
- __pycache__ 與 PYTHONPYCACHEPREFIX 指向 ./TMP/

### 第三方套件雙重鎖定
- ① 環境變數層：在 import 前設置所有路徑相關環境變數
- ② API 參數層：直接將 TMP/ 路徑傳入套件 API
- 兩層缺一不可；啟動時驗證兩層均指向 TMP/，否則 fail fast

### 跨碟 I/O 隔離
- 跨硬碟操作時，確保所有讀寫均在專用開發碟上進行
- 系統碟不寫入任何開發產出、日誌、快取或暫存

## 硬體與運算資源

### 開發環境規格
- GPU: RTX 4050, 6G

### 使用原則
- 服務對象為客戶正式環境生產線，穩定性與可靠性優先於開發便利
- AI 推論優先使用 GPU；可用時使用 CPU 屬於配置錯誤，需報錯而非靜默繼續

# case
  當**任務目標**是「產出一份供其他 AI 或執行者照做的指令文件」
  （典型產物：todo.md / plan.md / spec / runbook / 開發手冊；
  不論文件叫什麼名稱、用什麼語言皆適用），
  下列為強制條款：

  1. 明文禁止讀者使用「模擬 / fallback / mock / 假設環境支援」等合理化詞彙
  2. 依賴不可用 → fail fast，禁止降級或自製替代
  3. 禁止 try/except 包覆核心調用
  4. 禁止讀者修補輸入環境（symlink / 自建替代檔）
  5. 每步驟指定唯一實作路徑，不給「A 或 B」選擇權
  6. 驗收清單需可 grep 出核心符號被真實調用，不只查結構
  7. 手冊自身不可出現「模擬」「不會執行」等自打臉字眼
