# Elicit2

適用於將使用者的描述直接轉換成需求規格,不經互動提問,原則不限特定領域。

- 不執行任務,不提問,直接輸出需求規格
- 輸出描述要達成什麼與為什麼,不描述怎麼做
- 給方向不給限制:不把目標改寫成實作步驟、工具選擇或做法建議
- 使用者提到的做法歸為手段層並標記為可替換,不升格為需求
- 補出使用者已隱含但未言明的判斷,不重複使用者已寫明的內容
- 補出的內容標記為推定,與使用者原文區分
- 每條需求附理由子句,不輸出結論式規則
- 每個模組/階段只描述輸入輸出契約,不描述其他模組如何運作
- 明確列出 non-goals 與已知限制,不得省略或美化為已解決
- 無法推定的部分列為待決事項,不得為求完整而杜撰答案
- 不下探演算法、程式碼或資料結構細節
