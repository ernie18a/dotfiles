# 目的
- `/g/data/tv26101718708/.volume/.o/*.md` 是策略判斷邏輯摘要，共 568 份、3654 行、約 81 萬位元組。
- 痛點是注意力稀釋。資料直接交給 AI 討論時，它只會抽樣式地提出十幾個方案。
- 目標是產生讓新 session 的 AI 能取用全部資料的產物，並在其上去重收斂。整合方式有 3 種，各在一個獨立 session 執行，之後比較產物。

# 執行
- `/bulk 0` 建表，產物寫入 `.o/.table/`。
- `/bulk 1`、`/bulk 2`、`/bulk 3` 各用一種整合方式，讀取 `.o/*.md` 與 `.o/.table/`，產物分別寫入 `.o/.sort/`、`.o/.pair/`、`.o/.run/`。
- 不讀取其他整合方式的資料夾。原檔不修改。
- 逐份或逐批工作交給獨立 context 的 subagent，subagent 把結果寫入檔案，只回傳檔案路徑。每個 subagent 的簡報含目標、輸出格式、任務邊界。

# 建表
- 以規則行為單位逐份抽取，每列含原檔名、行號、規則類型、核心機制欄位、原句。規則類型為計算、做多、做空、出場。
- 先抽樣定義扁平的 canonical 欄位，值域用封閉清單限制，模型只能映射到既有欄位。
- 輸出後用程式正規化格式，統一 key，缺欄位補 null。
- 抽取後詢問是否有遺漏，有則補抽，設定輪數上限。
- 由程式確認 3654 行全部在表中，並確認每列原句確實存在於原檔。
- 失敗模式：同一概念會落在不同 key。抽取錯誤會直接進入後續查詢，程式無法修正。

# 去重原則
- 大同小異指核心判斷的數學結構相同。參數數值、同類指標替換、附加的濾網都屬於小異。判斷方向或觸發結構不同就是不同邏輯。
- 濾網與出場不作為分群依據，整理成該群的可選濾網與出場變體。出場或部位管理本身是核心時例外。
- 一份檔案含多個獨立邏輯時拆開，分別歸群。
- 每群以構成方式描述共同的核心邏輯，列出成員與各自的小異。獨立邏輯同樣成群。
- 每個歸群判定附依據，寫成表的欄位。

# 第 1 種：分類體系歸納
- 抽幾十份樣本，由 LLM 多步迭代產生分類體系，再逐份歸類全部檔案。
- 依計算、進場、出場、濾網等機制面向分群建階層，避免指標名稱主導分類。
- 失敗模式：直接提示常缺乏一致性與粒度。

# 第 2 種：候選對判定與全域一致性
- 以表的機制欄位縮小候選配對，或全兩兩比對約 16 萬對。
- LLM 對每對判定是否同一機制並給信心分數。每對對調順序各判一次，不一致者升級複審。每批 20–30 對。
- 以信心為邊權重，用 correlation clustering 移除造成不一致的弱邊。不直接用遞移閉包，局部錯誤會連鎖成混合不同邏輯的大群。

# 第 3 種：執行行為比對
- 把每份邏輯轉成可執行程式，在同一份 K 線資料上執行，比對做多、做空、出場訊號的重疊程度。訊號幾乎相同即大同小異。
- 直接讓 LLM 讀文字判斷等價效果有限，執行比對以數學行為判定。
- 失敗模式：轉碼錯誤會直接影響判定。

# 產物
- `.table/rules.tsv`：建表結果，3654 列。
- 各整合資料夾的 `groups.tsv`：每列為原檔名、行號、群組代號、判定依據。
- 各整合資料夾的群組說明：從群組代號可查到核心邏輯、可選濾網、出場變體與成員小異。
- `report.md`：遇到的失敗與處理，規則行覆蓋數，原句檢查通過率。

# 後續對話規則
- 可寫入 `.o` 的 CLAUDE.md，讓之後的 session 依此使用產物。
- 問題牽涉全體時，以程式查詢產物作答，不憑記憶或抽樣。
- 回答附覆蓋數，例如 568 份納入幾份、3654 行納入幾行。
- 需要語意判斷時，把查出的全部列分批逐一處理，每批 100 列以內。

# 筆記
- 單一 context 失效：模型漏掉重點多於捏造，罕見與複雜項目最容易漏，文件越長表現越差。長上下文會加劇抽取錯誤。關鍵內容位於長輸入中段時準確率最差。
- RAG 與向量不採用：top-k 檢索無法保證涵蓋全部文件，全域問題上最強 RAG 基線 F1 僅 1.51。先結構化再以查詢計算，效果明顯優於 RAG 與長上下文。
- 向量相似度不能判定邏輯等價，複雜否定任務上 embedding 準確率 33% 到 82%。向量只能產生候選配對。
- AI 讀表的準確率受列數影響遠大於格式。1000 筆時 Markdown-KV 約 60.7%，100 列時達 95% 以上。
- 圖譜、摘要樹、編譯 wiki 會壓縮資訊，不保證涵蓋全部文件，不採用。
- 待決：第 3 種要用哪一份 K 線資料。人工抽樣標註是否進行。`.o2` 如何處理。
