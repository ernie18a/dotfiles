# 目的
- 用法：`/qmd <問題>`。
- 透過 qmd MCP 從大量文件中找出最符合問題的資訊，主對話只讀精簡後的發現，不直接讀大量原文。
- 工作目錄為 `/tmp/qmd/<時間戳>/`，所有中間成果寫入檔案。

# 拆解
- 把問題拆成 3 到 8 個面向，涵蓋同義詞、相關概念、上位與下位概念、中英文用語。
- 每個面向寫出一組 `searches`：一條 `lex` 關鍵字、一條 `vec` 語意描述、一條 `hyde` 假想答案段落，並附 `intent` 說明問題背景。
- 面向清單寫入 `aspects.md`。

# 搜尋
- 每個面向交給一個 subagent 執行 qmd `query`，參數 `limit` 50、`candidateLimit` 200。
- subagent 把結果寫入 `cand/<面向>.tsv`，每列為 docid、path、score，只回傳檔案路徑。
- 主對話以 shell 合併全部 tsv，依 docid 去重，寫入 `cand.tsv`，記錄候選總數。

# 閱讀
- 把 `cand.tsv` 依 score 排序，每 10 份切成一批。
- 每批交給一個 subagent，以 qmd `get` 或 `multi_get` 讀全文，判斷每份是否與問題相關。
- 相關者寫出要點、適用條件、與其他做法的差異、來源 path 與行號。不相關者只記 docid 與一句理由。
- 結果寫入 `read/<批號>.md`，只回傳檔案路徑。

# 補搜
- 某個面向排名最後 10 份中仍有半數以上相關，代表該面向的結果被截斷。對該面向改用 `limit` 150、`candidateLimit` 500 重搜，新增候選回到閱讀步驟。
- 閱讀中發現候選未涵蓋的新概念時，新增面向回到搜尋步驟。
- 補搜最多 3 輪。

# 整合
- 全部 `read/*.md` 的相關條目合計 100 條以內時，主對話直接讀取整合。
- 超過時，每 100 條交給一個 subagent 歸納成主題，寫入 `merge/<批號>.md`，保留每個主題的來源清單，主對話讀取這一層。

# 回答
- 依主題作答，每項結論附來源 path 與行號，保留不同條件、差異與矛盾。
- 附覆蓋數：面向數、搜尋次數、候選總數、已讀份數、相關份數、補搜輪數。
- 結果屬於搜尋找到的候選範圍，不宣稱涵蓋全庫。
