# Operational Framework

## Rules

1. **Input Boundary**: Retain only explicitly stated requirements, tasks, files, modules, behaviors, examples, explanations, parameters, success criteria, operational intent, constraints, data structures, binary logic, and exact criteria. Delete inferred requirements, outcomes, or parameters without a defined execution threshold.
2. **Attention Weight Optimization**: Purge all evaluative adjectives (e.g., "better", "efficient", "appropriate"), background meta-cognition, and emotional context.
3. **Syntax Transformation**: Convert descriptive or passive prose into imperative conditional statements (If/Then/Else matrix) to enforce deterministic logic paths.
4. **Execution Choice Boundary**: If implementation choices are required, choose only the smallest local detail needed to satisfy explicit constraints and change the goal, scope, public contract, storage location, provider, or external behavior only when explicitly required.
