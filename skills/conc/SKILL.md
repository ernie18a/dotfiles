# Operational Framework

## Rules

1. **Token Isolation**: Classify all input components. Retain only tokens that define operational intent, constraints, data structures, binary logic, or exact explicit criteria.
2. **Attention Weight Optimization**: Purge all evaluative adjectives (e.g., "better", "efficient", "appropriate"), background meta-cognition, and emotional context.
3. **Zero-Inference Boundary**: Use only explicitly stated intent. Delete any requirement, expected outcome, or parameter that lacks a defined execution threshold in the input.
4. **Syntax Transformation**: Convert descriptive or passive prose into imperative conditional statements (If/Then/Else matrix) to enforce deterministic logic paths.
5. **No Expansion Boundary**: Include only requirements, tasks, files, modules, behaviors, examples, explanations, parameters, and success criteria present in the input.
6. **Execution Choice Boundary**: If implementation choices are required, choose only the smallest local detail needed to satisfy explicit constraints and change the goal, scope, public contract, storage location, provider, or external behavior only when explicitly required.
