# subt 下一次修改紀錄

## 交接目的

下一位接手者需繼續討論並修改 `subt` 技能，使它能處理「對話中的混亂自然語言」，不只處理指定的既有檔案。

## 已確認的困境

使用者執行 `$subt` 時，輸入可能是：

1. 既有檔案。
2. 尚未寫入檔案的對話內容。
3. 對話中混亂、重複、未完成的需求描述。
4. 對某個概念或需求的整理要求，未指定輸出檔案。

目前 `subt` 的描述將目標定義為 `editable artifact`，並要求先建立現有文字 `A`，再執行 delete、replace、consolidate、add。因此當目標檔案不存在時，執行者容易把「檔案不存在」當成主要問題，忽略使用者其實要求先用 MDL 整理意圖，再決定是否產生文件。

## 需求

`subt` 必須先判斷輸入載體：

```text
輸入是既有文件 → 壓縮文件
輸入是對話內容 → 壓縮意圖與約束
輸入是概念要求 → 建立最小必要規格
```

檔案不存在時，不得自行停止；應將目前輸入視為 `A = conversation state`，把使用者要求視為 `U`，抽取 `I`，再依 MDL 產生最小必要結果。是否寫入新檔案只是輸出動作，不是 `subt` 的核心對象。

## 下一次修改應檢查

1. `Role` 是否從「editable artifacts」擴展為「documents, conversation state, and requirements」。
2. `Premise Check` 是否允許 `A` 為對話，而非強制要求檔案存在。
3. `Edit Order` 是否適用於「刪除混亂內容、合併重複意圖、補出必要結構」。
4. `Handoff Report` 是否能回報意圖整理結果，而不只回報檔案 edit diff。
5. 是否明確禁止因缺少輸出檔案而中止，但仍禁止臆測未提供的需求。

## 不應改變的核心不變量

- MDL：保留必要且充分的意圖與約束。
- 不以主觀形容詞定義品質。
- 不把推測內容當成使用者意圖。
- 每個保留的規則都必須能說明其必要性。
- 產生新文件時，文件是結果，不是技能執行前提。
